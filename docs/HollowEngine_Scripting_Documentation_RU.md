# 1. Введение

HollowEngine позволяет писать игровые сценарии на языке Kotlin, адаптированном для выполнения непосредственно внутри Minecraft.

Основная идея скриптового движка заключается в том, что разработчику не требуется каждый раз создавать полноценный Java/Kotlin-класс, мод и отдельную систему регистрации. В `.kts`-файле можно писать код непосредственно в корневом пространстве файла.

При этом обычные возможности Kotlin не запрещены: при необходимости можно создавать собственные функции, классы и вложенные структуры.

Скрипты предназначены прежде всего для:

- сюжетных событий;
- NPC;
- катсцен;
- диалогов;
- взаимодействия с игроками;
- изменения моделей;
- анимаций;
- игровых условий;
- работы с командами и игровым миром;
- рецептов;
- небольших игровых расширений.

Для работы со скриптами рекомендуется знать основы Kotlin.

# 2. Типы скриптов

HollowEngine выделяет три основных типа скриптов.

| Тип | Расширение | Назначение |
|---|---|---|
| Mod | `.mod.kts` | Выполняется во время загрузки игры |
| Story Event | `.se.kts` | Сюжетное событие, запускаемое внутри мира |
| Content | `.content.kts` | Скрипт игрового контента, в частности рецептов |

Примеры:

```text
initialization.mod.kts
intro.se.kts
chapter_01.se.kts
diamond_sword.content.kts
```

### Mod

Mod-скрипт выполняется аналогично обычной инициализации мода во время загрузки игры.

Он может использоваться как точка регистрации или подготовки игровых систем.

### Story Event

Story Event (`se`) предназначен для сценариев:

- NPC;
- диалогов;
- катсцен;
- последовательностей действий;
- условий;
- ветвлений;
- сохранения состояния сюжетной линии.

### Content

Content-скрипт запускается при перезагрузке рецептов, в том числе через `/reload`.

# 3. Файлы и структура проекта

Скрипты находятся в:

```text
.minecraft/hollowengine/scripts/
```

Внутри можно создавать дополнительные директории.

Например:

```text
scripts/
├── events/
│   ├── chapter_01/
│   │   ├── intro.se.kts
│   │   └── meeting.se.kts
│   └── chapter_02/
│       └── battle.se.kts
│
├── recipes/
│   └── custom_recipe.content.kts
│
└── initialization.mod.kts
```

Это особенно полезно для крупных сюжетных карт.

Рекомендуется:

- использовать нижний регистр;
- не использовать пробелы;
- использовать `_` для разделения слов;
- разделять события по главам или системам.

# 4. Package и импорт

## 4.1. Package

Чтобы избежать конфликтов имён, скрипты можно помещать в разные пакеты.

Путь:

```text
scripts/ru/hollowhorizon/my_super_modpack/intro.se.kts
```

соответствует:

```kotlin
package ru.hollowhorizon.my_super_modpack
```

В `package` используются точки, а не `/`.

## 4.2. Импорт другого скрипта

Скрипт можно импортировать аннотацией:

```kotlin
@file:Import("../path/to/file.kts")
```

Путь является относительным относительно текущего скрипта.

Важно: обычные переменные импортированного скрипта создаются заново. Поэтому нельзя рассчитывать, что объект, созданный в одном скрипте, автоматически станет тем же объектом после импорта в другой.

Отдельно документация упоминает `runtime`-переменные как исключение.

# 5. Компиляция и IDE

При первом запуске `.kts`-скрипт компилируется.

Время компиляции зависит от:

- размера скрипта;
- количества импортов;
- используемых библиотек;
- производительности компьютера.

Документация указывает диапазон от примерно 5 секунд до 3–5 минут.

После успешной компиляции скрипт упаковывается в JAR, поэтому следующие запуски происходят значительно быстрее.

Если исходный `.kts` изменён, потребуется новая компиляция.

Если скрипт долго не запускается и при этом нет ошибок, документация рекомендует проверить установку HollowCore. Для полноценной компиляции необходима не Lite-версия.

## IntelliJ IDEA

Для полноценного автодополнения рекомендуется работать с исходниками HollowEngine.

Общий порядок:

1. Клонировать репозиторий HollowEngine.
2. Открыть проект в IntelliJ IDEA.
3. Дождаться настройки и индексации.
4. Открыть Gradle.
5. Выполнить:

```text
HollowEngine
└── Tasks
    └── forgegradle
        └── runs
            └── genIntellijRuns
```

6. Собрать JAR:

```text
Tasks
└── build
    └── jar
```

7. Запустить игру через созданную конфигурацию.

В режиме разработки скрипты размещаются в:

```text
run/hollowengine/scripts/
```

После добавления нового скрипта IntelliJ может выполнить дополнительную индексацию.

# 6. Сюжетные события

Сюжетное событие — основной механизм HollowEngine для построения игровых сценариев.

Оно может описывать последовательность:

```text
создать NPC
    ↓
NPC идёт в точку
    ↓
ожидание
    ↓
NPC говорит
    ↓
игрок выбирает ответ
    ↓
ветвление
    ↓
катсцена
```

Главная концепция Story Event — **граф узлов**.

Каждое действие является узлом.

Например:

```text
NPC Creation Node
        ↓
Movement Node
        ↓
Wait Node
        ↓
Dialogue Node
```

Сложные узлы могут содержать другие узлы.

Например:

```text
If
├── true branch
│   ├── dialogue
│   └── animation
│
└── false branch
    └── dialogue
```

Цикл аналогично может содержать собственную последовательность узлов.

---

# 7. Стадии выполнения сюжетного скрипта

У Story Event есть две фундаментальные стадии.

## 7.1. Загрузка

Во время загрузки код превращается в структуру узлов и передаётся машине состояний.

Именно поэтому обычный Kotlin-код внутри Story Event нельзя всегда воспринимать как обычную последовательную программу.

Многие методы не выполняют действие немедленно.

Они создают узел, который будет выполнен позже.

## 7.2. Исполнение

После построения графа начинается фактическое выполнение события.

Именно здесь:

- NPC перемещается;
- проигрывается анимация;
- выполняется ожидание;
- показывается диалог;
- проверяются условия;
- изменяются сохраняемые значения.

# 8. Делегированные и сохраняемые переменные

В Story Event переменные часто используются через делегаты.

Пример:

```kotlin
var reputation by saveable { 0 }
```

Это не просто обычная переменная.

Она позволяет движку сохранить состояние.

Значение можно получить:

```kotlin
npc say { "Твоя репутация: $reputation" }
```

А изменить во время исполнения:

```kotlin
next {
    reputation++
}
```

`next` нужен, когда код должен быть выполнен именно во время прохождения события, а не во время построения его графа.

Концептуально сохранённая переменная состоит из операций:

```text
создать значение
       ↓
получить значение
       ↓
изменить значение
```

Это особенно важно для:

- репутации;
- прогресса квеста;
- флагов;
- выбора игрока;
- состояния персонажей;
- этапов сюжетной линии.

# 9. Запуск сюжетных событий

Основная команда:

```text
/hollowengine start-script <цель> <файл>
```

Важный момент: целью является не отдельный игрок, а его команда.

Поэтому Story Event изначально рассчитан на командное выполнение.

Для запуска события при первом входе игрока используется:

```kotlin
@file:EntryPoint
```

Эта аннотация сообщает движку, что скрипт должен запускаться для нового игрока.

# 10. Действия: условия и ветвления

В Story Event не рекомендуется использовать обычные:

```kotlin
if
else
```

на стадии построения скрипта.

Для сюжетных условий используется специальный механизм:

```kotlin
If({ <условие> }) {
    // действие
} Else {
    // альтернативное действие
}
```

Пример:

```kotlin
If({ reputation >= 10 }) {
    npc say { "Я тебе доверяю." }
} Else {
    npc say { "Я пока тебе не доверяю." }
}
```

Главная причина использования `If` заключается в том, что условие должно проверяться во время исполнения события.

Условием может быть любое выражение, возвращающее:

```text
Boolean
```

то есть:

```text
true
```

или:

```text
false
```

---

# 11. Действия: асинхронное выполнение

Для параллельного выполнения используется:

```kotlin
async {
    // действия
}
```

Например:

```kotlin
async {
    npc playLooped { "idle" }
}
```

Асинхронный блок выполняется параллельно с основным сценарием.

Внутри него разрешены обычные действия Story Event:

- NPC;
- циклы;
- условия;
- другие действия.

Асинхронную задачу можно сохранить в переменную:

```kotlin
val task = async {
    // действия
}
```

После этого:

```kotlin
task.stop()
```

останавливает её.

А:

```kotlin
task.resume()
```

возобновляет выполнение.

Это особенно полезно для фоновых и бесконечных циклов.

NPC могут:

- иметь собственные размеры;
- показывать имя;
- использовать анимации;
- перемещаться;
- смотреть в определённом направлении;
- говорить;
- использовать предметы;
- взаимодействовать с блоками;
- получать цель;
- атаковать;
- исчезать.

# 13. Создание NPC

Базовый шаблон:

```kotlin
val npc by NPCEntity.creating {
    name = "Виталик"

    model = "hollowengine:models/entity/player_model.gltf"

    attributes = Attributes(
        "minecraft:generic.max_health" to 100f
    )

    size = 0.6f to 0.8f

    showName = true

    transform = Transform(
        tX = 1.5f
    )

    animations[AnimationType.IDLE] = "<animation>"

    world = "minecraft:overworld"

    pos = pos(x, y, z)
}
```

### Основные свойства

`name`

Имя NPC.

`model`

ResourceLocation модели.

`attributes`

Атрибуты персонажа.

`size`

Размер хитбокса.

`showName`

Показывать ли имя над персонажем.

`transform`

Начальное перемещение, вращение и масштаб модели.

`animations`

Замена стандартных анимаций.

`world`

Измерение.

`pos`

Начальная позиция.

При выполнении создания NPC движок создаёт персонажа либо использует уже существующего NPC, если соответствующий объект уже присутствует.

## Случайная позиция

Для случайной позиции рядом с игроком команды:

```kotlin
pos = team.randomPos()
```

Можно передать радиус:

```kotlin
pos = team.randomPos(25f)
```

# 14. Настройка моделей NPC

Модель задаётся через ResourceLocation:

```text
namespace:path
```

Например:

```text
hollowengine:models/entity/player_model.gltf
```

Для предметов в руках модель должна содержать соответствующие кости/группы.

Правая рука:

```text
RightHandItem
```

Левая рука:

```text
LeftHandItem
```

Эти кости могут использоваться не только для отображения предмета, но и в анимациях.

Например, это позволяет делать:

- доставание меча;
- удержание предмета;
- бой;
- анимации с предметами.

# 15. Предметы и взаимодействие NPC с миром

## Сообщение

NPC может написать:

```kotlin
npc say { "Привет!" }
```

## Бросок предмета

```kotlin
npc dropItem {
    item("minecraft:apple")
}
```

Для удобного получения полного описания предмета можно взять предмет в основную руку и использовать:

```text
/hollowengine hand
```

Команда позволяет получить данные предмета, включая количество и NBT.

## Предмет в правой руке

```kotlin
npc giveRightHand {
    item("minecraft:apple")
}
```

## Предмет в левой руке

```kotlin
npc giveLeftHand {
    item("minecraft:apple")
}
```

## Запрос предметов

NPC может потребовать от игрока предметы:

```kotlin
npc requestItems {
    text = "Принеси мне эти предметы:"
    +item("minecraft:apple")
}
```

## Использование блока

```kotlin
npc useBlock {
    pos(x, y, z)
}
```

Получить координаты блока, на который смотрит игрок, можно командой:

```text
/hollowengine pos
```

# 17. Анимации NPC

Названия доступных анимаций можно посмотреть через:

```text
/hollowengine model <путь к модели>
```

Есть несколько режимов.

## Однократное воспроизведение

```kotlin
npc playOnce {
    "animationName"
}
```

## Зацикленное воспроизведение

```kotlin
npc playLooped {
    "animationName"
}
```

## Остановка

```kotlin
npc stop {
    "animationName"
}
```

## Детальная настройка

```kotlin
npc play {
    animation = "animationName"

    layerMode = LayerMode.ADD

    playType = PlayMode.ONCE

    speed = 1f
}
```

### LayerMode

`ADD`

Добавляет новую анимацию поверх текущей.

`OVERWRITE`

Полностью заменяет другие анимации.

### PlayMode

Доступны:

```text
ONCE
LOOPED
LAST_FRAME
REVERSED
```

`ONCE` — проиграть один раз.

`LOOPED` — проигрывать циклически.

`LAST_FRAME` — остановиться на последнем кадре.

`REVERSED` — циклическое воспроизведение с обратным проигрыванием.

# 18. Игроки

Story Event работает с игроками через команду.

Основная концепция:

```text
team
```

То есть сценарий может быть ориентирован не только на одного игрока, а на группу.

Конкретного игрока можно получить по имени:

```kotlin
val player by team[{ "Ник Игрока" }]
```

---

# 19. Модели игроков

После получения игрока можно изменить его модель:

```kotlin
player configure {
    model = "hollowengine:models/entity/player_model.gltf"

    animations[AnimationType.IDLE] = "animationName"

    textures["original_name"] =
        "hollowengine:textures/skins/my_skin.png"

    transform = Transform(
        tX = 1.5f
    )
}
```

### model

Изменяет модель игрока.

### animations

Позволяет заменить стандартные анимации.

### textures

Позволяет заменить текстуры модели.

### transform

Позволяет изменить:

- положение;
- вращение;
- масштаб.

## Возврат стандартной модели

Используется специальное значение:

```kotlin
model = "%NO_MODEL%"
```

```kotlin
    layerMode = LayerMode.ADD
    playType = PlayMode.ONCE
    speed = 1f
}
```

Поддерживаются те же основные режимы:

```text
LayerMode.ADD
LayerMode.OVERWRITE

PlayMode.ONCE
PlayMode.LOOPED
PlayMode.LAST_FRAME
PlayMode.REVERSED
```

# 21. Диалоги

Диалог представляет собой специальное пространство Story Event:

```kotlin
dialogue {
    // действия диалога
}
```

Персонажа, который должен участвовать в диалоге, рекомендуется создать до входа в `dialogue`.

Например:

```kotlin
val npc by NPCEntity.creating {
    ...
}

dialogue {
    ...
}
```

Внутри пространства диалога некоторые действия меняют своё поведение.

Например:

```kotlin
npc say { "Привет!" }
```

в обычном пространстве может отправить сообщение в чат.

В пространстве `dialogue` оно становится репликой в окне диалога.

---

# 22. Текст в диалоге

## Реплика NPC

```kotlin
npc say {
    "Привет!"
}
```

## Реплика команды

```kotlin
team send {
    "Привет!"
}
```

## Произвольный авторский текст

```kotlin
send {
    name = "Неизвестный"
    text = "Привет, мы раньше не встречались?"
}
```

`name` задаёт имя говорящего.

`text` задаёт отображаемый текст.

# 23. Выборы

Выборы доступны внутри пространства:

```kotlin
dialogue {
    ...
}
```

Синтаксис:

```kotlin
choice {
    "Ваш вариант 1" {
        // действия
    }

    "Ваш вариант 2" {
        // действия
    }
}
```

Можно добавить любое количество вариантов:

```kotlin
choice {
    "Да" {
        // ветка 1
    }

    "Нет" {
        // ветка 2
    }

    "Я не знаю" {
        // ветка 3
    }
}
```

Выбор завершает свою часть диалога после выполнения соответствующей ветки.

Диалог завершается, когда больше не остаётся реплик и выборов.

# 24. Катсцены

Катсцена строится из тех же узлов Story Event, но дополнительно использует управление камерой и переходами.

Концептуальная структура:

```text
создать NPC
      ↓
расставить персонажей
      ↓
переместить камеру
      ↓
проиграть анимацию
      ↓
показать реплику
      ↓
переход камеры
      ↓
следующий кадр
```

Главный принцип — катсцена не является отдельной магической системой. Она строится как последовательность узлов Story Event.

---

# 25. Мир и время

Скрипты могут взаимодействовать с состоянием игрового мира.

Временные действия следует выполнять как часть Story Event, если изменение должно быть синхронизировано с сюжетом.

Например, концептуально:

```text
начало сцены
    ↓
изменение времени
    ↓
ожидание
    ↓
диалог
```

При использовании временных действий необходимо учитывать, что Story Event работает через машину состояний, поэтому действие, которое должно произойти именно во время исполнения, не следует бездумно выполнять на стадии загрузки.

# 26. Эффекты и частицы

HollowEngine поддерживает визуальные эффекты, включая частицы.

Внутри сценариев эффекты можно использовать как отдельные узлы последовательности:

```text
NPC говорит
    ↓
частицы
    ↓
анимация
    ↓
переход
```

Это позволяет использовать частицы в:

- магических эффектах;
- ударах;
- появлении персонажа;
- исчезновении;
- телепортации;
- катсценах;
- визуальных акцентах.

# 27. Список событий

Для сложного проекта удобно разделять события на отдельные файлы.

Пример:

```text
events/
├── chapter_01/
│   ├── intro.se.kts
│   ├── village.se.kts
│   └── first_battle.se.kts
│
├── chapter_02/
│   ├── investigation.se.kts
│   └── confrontation.se.kts
│
└── common/
    ├── death.se.kts
    └── ending.se.kts
```

Такой подход позволяет не превращать одну сюжетную линию в огромный `.kts`.

# 28. Интерполяции

Интерполяция используется для управления характером изменения величины во времени.

Вместо:

```text
A → B
```

можно получить:

```text
A ── плавное изменение ──→ B
```

Это особенно полезно для:

- движения;
- камеры;
- трансформаций;
- визуальных эффектов.

Доступны:

```text
Interpolation.LINEAR

Interpolation.SINE_IN
Interpolation.SINE_OUT
Interpolation.SINE_IN_OUT

Interpolation.QUAD_IN
Interpolation.QUAD_OUT
Interpolation.QUAD_IN_OUT

Interpolation.CUBIC_IN
Interpolation.CUBIC_OUT
Interpolation.CUBIC_IN_OUT

Interpolation.QUART_IN
Interpolation.QUART_OUT
Interpolation.QUART_IN_OUT

Interpolation.QUINT_IN
Interpolation.QUINT_OUT
Interpolation.QUINT_IN_OUT

Interpolation.EXPO_IN
Interpolation.EXPO_OUT
Interpolation.EXPO_IN_OUT

Interpolation.CIRC_IN
Interpolation.CIRC_OUT
Interpolation.CIRC_IN_OUT

Interpolation.BACK_IN
Interpolation.BACK_OUT
Interpolation.BACK_IN_OUT

Interpolation.ELASTIC_IN
Interpolation.ELASTIC_OUT
Interpolation.ELASTIC_IN_OUT

Interpolation.BOUNCE_IN
Interpolation.BOUNCE_OUT
Interpolation.BOUNCE_IN_OUT
```

Кратко:

- `LINEAR` — равномерное изменение;
- `SINE` — плавное синусоидальное;
- `QUAD/CUBIC/QUART/QUINT` — степенные кривые;
- `EXPO` — экспоненциальное;
- `CIRC` — круговое;
- `BACK` — движение с небольшим выходом за конечную точку;
- `ELASTIC` — упругое движение;
- `BOUNCE` — эффект отскока.

Суффиксы:

```text
_IN
_OUT
_IN_OUT
```

определяют, в какой части движения применяется кривая.

# 29. Полезные принципы проектирования

## 29.1. Помнить о двух стадиях

В Story Event есть принципиальная разница:

```text
загрузка
```

и:

```text
исполнение
```

Если код должен реагировать на состояние мира, игрока или NPC в момент прохождения, он должен быть представлен узлом/действием, которое выполняется на второй стадии.

## 29.2. Не использовать обычный if без необходимости

Вместо:

```kotlin
if (reputation > 10) {
    ...
}
```

в Story Event следует использовать:

```kotlin
If({ reputation > 10 }) {
    ...
}
```

## 29.3. Использовать saveable для сюжетного состояния

Например:

```kotlin
var reputation by saveable { 0 }
```

Это позволяет сделать переменную частью сохраняемого состояния события.

## 29.4. Разделять большие сценарии

Не следует создавать один огромный:

```text
story.se.kts
```

Лучше:

```text
chapter_01/
chapter_02/
chapter_03/
```

и отдельные события внутри.

## 29.5. Использовать async только там, где нужен параллелизм

Например:

```kotlin
async {
    npc playLooped { "idle" }
}
```

полезно, когда действие должно продолжаться параллельно основной сцене.

# 30. Минимальный пример сюжетного события

Ниже приведён компактный пример, объединяющий основные принципы.

```kotlin
package example.chapter_01

var reputation by saveable { 0 }

val npc by NPCEntity.creating {
    name = "Незнакомец"
    model = "hollowengine:models/entity/player_model.gltf"
    showName = true
    world = "minecraft:overworld"
    pos = team.randomPos(10f)
}

npc say {
    "Эй! Помоги мне."
}

dialogue {
    npc say {
        "Ты можешь мне помочь?"
    }

    choice {
        "Да" {
            npc say {
                "Спасибо."
            }

            next {
                reputation++
            }
        }

        "Нет" {
            npc say {
                "Жаль."
            }
        }
    }
}

If({ reputation > 0 }) {
    npc say {
        "Я запомню твою помощь."
    }
}
```

Структура такого события:

```text
создание NPC
      ↓
реплика
      ↓
диалог
      ↓
выбор
 ┌────┴────┐
 ↓         ↓
Да         Нет
 ↓         ↓
+1         отказ
 └────┬────┘
      ↓
проверка reputation
```
