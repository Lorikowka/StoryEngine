# Narrative HUD — документация

## Обзор

Narrative HUD — модуль «сюжетного чата»: сервер отправляет отформатированную
реплику (как `/tellraw`) с именем говорящего и иконкой NPC, клиент показывает
её по центру-низу экрана с эффектом печатной машинки.

## Архитектура

| Класс | Сторона | Назначение |
|---|---|---|
| `command/StoryTellCommand.java` | сервер | команда `/storytell` |
| `network/S2CStoryChatPacket.java` | обе | пакет: спикер, iconId, `Component` текста |
| `network/NarrativeNetworking.java` | обе | регистрация пакета на канале `QuestNetworking.CHANNEL` (id=2) + рассылка |
| `narrative/NarrativeMessage.java` | клиент | модель одного сообщения в очереди |
| `narrative/NarrativeChatManager.java` | клиент | очередь сообщений + тик-логика печатной машинки |
| `client/DynamicHeadManager.java` | клиент | читает `.png` иконки NPC напрямую с диска, регистрирует как `DynamicTexture` |
| `client/NarrativeOverlay.java` | клиент | `RenderGuiOverlayEvent` + `ClientTickEvent`: сама отрисовка на экране |
| `client/TextureBlitHelper.java` | клиент | служебный класс, даёт доступ к protected `blit()` вне `Screen` |

## Команда `/storytell`

```text
/storytell <targets> <speaker> <icon> <message>
```

- `<targets>` — игроки-получатели (`EntityArgument.players()`);
- `<speaker>` — имя говорящего, в кавычках, если с пробелами: `"Староста"`;
- `<icon>` — имя файла иконки без `.png` (например `old_man`).
  `none` — без иконки;
- `<message>` — JSON-компонент текста, как в `/tellraw`
  (например `{"text":"Привет!","color":"gold"}`).

Требует permission level 2. Пример:

```text
/storytell @a "Староста" old_man {"text":"Постойте... кажется, ключ вовсе не в доме."}
```

## Иконки NPC

Кладутся вручную (или генерируются другим инструментом) в:

```
config/story_engine/heads/<icon_id>.png
```

`DynamicHeadManager` читает файл через `NativeImage.read()`, регистрирует как
`DynamicTexture` под `story_engine:heads/<icon_id>` **в обход системы
ресурс-паков** — то есть текстуру не нужно паковать в джарник мода или в
ресурс-пак, файл читается прямо с диска сервера/клиента при первом
использовании иконки. Результат (в том числе отрицательный, если файла нет)
кэшируется, повторных чтений с диска для одной и той же иконки не происходит,
пока не вызван `DynamicHeadManager.clearCache()`.

Если `<icon>` = `none`, либо файл не найден — сообщение рисуется без иконки
(текст просто начинается левее).

## Очередь и печатная машинка

`NarrativeChatManager`:

- сообщения от `S2CStoryChatPacket` складываются в `Queue<NarrativeMessage>`,
  чтобы несколько реплик подряд не накладывались друг на друга;
- каждый клиентский тик (`ClientTickEvent`, регистрируется в
  `NarrativeOverlay`) увеличивает счётчик и пересчитывает, сколько символов
  сообщения должно быть видно (по умолчанию 1 тик/символ = 20 симв./сек);
- после полной отрисовки сообщение держится на экране ещё
  `max(30 тиков, 2 × длина текста в тиках)`, затем менеджер берёт следующее
  сообщение из очереди;
- `NarrativeChatManager.skipTyping()` — публичный метод, чтобы сразу
  показать текст целиком (например, по клику мыши — сам биндинг под клик
  пока не добавлен, это точка расширения на будущее).

## Отрисовка

`NarrativeOverlay` вешается на `RenderGuiOverlayEvent.Post`, фильтруя по
`VanillaGuiOverlay.HOTBAR` (рендерится ровно один раз за кадр и не рисуется,
когда открыт любой `Screen` — инвентарь, меню квестов и т.п., так что
оверлей автоматически не мешает GUI).

Макет (как в ТЗ):

- `Y = высота экрана - 60`, по центру по X (ширина блока 300px);
- слева — иконка NPC 32×32 (если есть);
- справа от иконки, сверху — имя спикера (`Font.drawShadow`, жёлтый `0xFFFF55`);
- под именем — текст с автопереносом (`Font.split`), обычный белый.

### Ограничение эффекта печатной машинки

Пока текст печатается посимвольно, форматирование упрощено до **единого**
стиля корневого `Component` (цвет/курсив/жирность всего сообщения целиком).
Если в JSON несколько разноцветных "прогонов" текста в одном сообщении, во
время анимации печати они временно покажутся одним цветом — а как только
сообщение допечатается целиком, на экран выводится оригинальный `Component`
**со всем форматированием как в `/tellraw`**, без каких-либо упрощений.
Причина: в 1.19.2 нет готового API "взять первые N символов Component с
сохранением стилевых границ", а собственная реализация ради анимации это
избыточно рискованно ради чисто визуального эффекта. Если для конкретного
сценария это критично — самый простой обход: слать несколько подряд идущих
`/storytell` с разным цветом на разные части фразы вместо одного сообщения
с несколькими цветовыми прогонами.

## Как расширять

- Добавить реакцию на клик (`skipTyping()`) — повесить обработчик мыши в
  `NarrativeOverlay` или через `ScreenEvent`/`InputEvent`.
- Добавить звук при появлении нового сообщения — проигрывать в момент,
  когда `NarrativeChatManager.tick()` переключает `current` с `null` на
  новое сообщение.
- Поддержать несколько одновременных "говорящих" (сейчас рисуется только
  одно текущее сообщение) — потребует расширения `NarrativeOverlay` под
  несколько слотов вместо одного.
