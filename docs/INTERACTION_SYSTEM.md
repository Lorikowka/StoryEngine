# Interaction Hint System — документация

> Номера разделов (§N) соответствуют ссылкам в Javadoc модуля
> `com.storyengine.interaction`.

## §1 Обзор

Interaction Hint System добавляет генеральные подсказки взаимодействия
с миром без единого JSON-файла:

- если под крестовиной игрока интерактибль (дверь, сундук, верстак, кровать,
  рамка с предметом, сущность и т.п.), в левом нижнем углу экрана
  показывается HUD «[F] Действие» (название действия резолвится через
  `VanillaActionResolver`, `story_engine.action.*` из lang-файлов);
- близкие интерактиблы подсвечиваются кольцами-маркерами прямо в мире;
- клавиша F работает как фолбэк: выполняет ванильное использование
  блока/сущности под крестовиной (аналог правого клика);
- нативный серверный подхват предметов из рамок (item frame pickup)
  реализован в `ItemFramePickupHandler`;
- **в режимах без креатива ПКМ по интерактиблу подавлен**: ванильное
  использование идёт только через F. В креативе ПКМ работает как обычно
  (удобно для сборки). Подавление реализовано клиентским событием
  `InteractionKeyMappingTriggered` в `InteractionInputHandler`, оно отменяет
  только физический клик право кнопкой — F-фолбэк ходит напрямую в
  `MultiPlayerGameMode` и это событие не триггерит.

Система не имеет серверного состояния и JSON-конфигурации точек — всё
определяется ванильными интерактивными блоками/сущностями.

Серверная подсказка от Trigger System (см. `docs/MOD_REPORT-2026-09-12.md` §7,
ТЗ `Story_Engine_Trigger_System_v1_TZ_edited.md`): если под крестовиной игрока
сервер резолвит интерактивный триггер — его `hint_label` (`TriggerHintClientState`)
имеет **приоритет** над клиентским `VanillaActionResolver`; иначе HUD
показывает ванильное действие как раньше.

## §2 HUD «[F] Действие» и маркеры

Секция `interactionHintCustomization` в `config/story_engine-client.toml`:

- `enabled` — главный выключатель HUD/маркеров/F-фолбэка;
- `useTexture` — рисовать плашку HUD поверх кастомной текстуры
  `config/story_engine/menu/interaction_hint.png` (по умолч. `true`);
  при `false` плашка рисуется сплошной заливкой + рамкой;
- `layout.scanRadius` / `layout.maxMarkers` — радиус сканирования окрестности
  и лимит видимых маркеров (0–8 блоков, по умолч. 5);
- `layout.leftOffset` / `layout.bottomOffset` — позиция HUD от левого
  и нижнего края экрана;
- `colors.fill` / `colors.border` / `colors.text` — цвета заливки, рамки
  и текста плашки (актуальны при `useTexture = false`);
- `colors.marker` / `colors.markerAimed` — цвета мирового кольца и кольца
  прицеленной цели.

Плашка `interaction_hint.png` (64×32, скруглённый прямоугольник с рамкой)
рисуется через 9-slice (`TextureBlitHelper.blitNineSlice`) — углы и толщина
рамки не искажаются при любой ширине текста. Анимация:
slide-in слева + масштабный pulse + плавное затухание при потере цели.

Мировые кольца-маркеры (`InteractionCrosshairMarker`) отрисовываются
процедурно (без текстур).

## §3 Обнаружение целей (InteractionHintScanner)

Каждый клиентский тик:

1. **Цель взгляда** берётся из `mc.hitResult` (окклюзия уже учтена ванильным
   рейкастом). Для блока — классификация через `VanillaActionResolver`
   (двери, сундуки, рычаги, кровати, колокол и т.п.); если действие не
   известно, но у блока есть `MenuProvider` — показывается generic «Использовать».
   Для сущности — `getEntityAction` (рамки, вагонетки, лодки и т.п.).
2. **Близкие цели** — куб `scanRadius` вокруг игрока (обновление раз в 4 тика)
   для мировых колец-маркеров. Лишние цели (больше `maxMarkers`) сортируются
   по дистанции и обрезаются.

Пары блоков (двери, двойные сундуки) центрируются как единая цель — маркер/луч
бьются в общий центр обеих половин.

Результат сохраняется в `InteractionHintState` (`aimedAction`/`aimedPos` +
список близких целей) и читается HUD'ом и маркерами.

## §4 Ввод (InteractionInputHandler)

- Клавиша F (`key.story_engine.interact`, по умолчанию F) при нажатии
  выполняет F-фолбэк: ванильное использование цели взгляда —
  `useItemOn` (блок) или `interactAt`/`interact` (сущность, рамка) через
  `MultiPlayerGameMode`. Дёшево, не конфликтует с ПКМ.
- Клавиша выключена при открытом GUI/диалоге и при выключенном хинт-конфиге.
- ПКМ-блокировка (§1): на `InputEvent.InteractionKeyMappingTriggered`, когда
  игрок не в креативе и цель взгляда классифицирована `VanillaActionResolver`
  (блок с действием или `MenuProvider`, сущность с действием) — событие
  отменяется (`setCanceled(true)`). F-фолбэк это событие не триггерит,
  поэтому остаётся рабочим способом взаимодействия в выживании.

Клиент не отправляет серверу никаких пакетов взаимодействия: всё исполнение
идёт через ванильный клиент-серверный путь (use item on block / interact).

## §5 Серверная часть

- `ItemFramePickupHandler` — серверный подхват предметов из рамок
  (`PlayerInteractEvent`): левый клик забирает предмет, как в кликабельном
  референсе Interaction Hint. Конфигурационные настройки не читает.
- Серверная триггерная подсказка (Trigger System, этап 6): клиент раз в 10
  тиков шлёт цель под прицелом (`C2SCrosshairPacket`, id 14), сервер
  резолвит подходящий триггер (`TriggerHintService`) и синхронизирует его
  серверным пакетом `S2CSyncTriggerHintsPacket` (id 13). Подробнее — в
  MOD_REPORT §7 и ТЗ триггеров.

## §6 Конфигурация

Вся настройка — только клиентская (`MenuCustomizationConfig`, раздел
`interactionHintCustomization` в `story_engine-client.toml`). Серверный код
конфиг не читает.
