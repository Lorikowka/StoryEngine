# StoryEngine / HollowEngine — известные грабли (GOTCHAS)

Зафиксированные проблемы модов, из-за которых контент падает в рантайме.
Цель — не повторять их при авторинге квестов/диалогов/скриптов.

---

## 1. Quest JSON: у задачи ОБЯЗАТЕЛЬНО непустое `description` (иначе NPE на входе)

**Симптом:** при входе игрока в мир — `java.lang.NullPointerException: Cannot invoke "String.length()" because "p_130073_" is null`
в `com.storyengine.network.QuestNetworking$S2CSyncQuestDataPacket.encodeTask`, далее
`Couldn't place player in world` и клиент показывает «неверные данные игрока».
Квест при этом грузится нормально (`[StoryEngine] Загружено квестов: 1`), падение — только при синхронизации на логине.

**Причина (баг мода):** `encodeTask` вызывает `writeUtf(description)`, не проверяя на `null`.
Мод не валидирует квест при загрузке и не подставляет пустую строку.

**Требование контента:** у каждой задачи (`tasks[]`) должны быть непустые `id`, `title` **и `description`**.
Пример корректной задачи:
```json
{"id":"leon_meeting","title":"Знакомство с Леоном","description":"Допрос свидетеля Леона Вальтера.","type":"MANUAL"}
```
Также безопасно указывать у квеста `"prerequisites": []` и `"rewards": {}` (как в документированном примере),
чтобы не полагаться на дефолты сериализатора.

**Как ловить до запуска:** расширенная проверка (см. ниже) должна требовать `description`+`title` у каждой задачи.

## 2. Dialogue-синхронизация — аналогичный риск null-полей (НЕ ПОДТВЕРЖДЕНО)

Квест упал ДО того, как дошла очередь до синхронизации диалогов, поэтому грабля
с `DialogueNetworking` пока не проявилась. Вероятно, то же поведение: узлы/`_meta`
должны содержать все строковые поля, которые мод пишет в пакет (`text`, `speaker`,
заголовок `_meta` и т.п.). Если после фикса квеста появится похожий NPE на
`DialogueNetworking` — дописать недостающие поля в соответствующие `entry.json`/`_meta.json`
и добавить правило сюда.

---

## 3. NPC right-click → команда — документация отсутствует

Локальные доки только ссылаются на внешнюю страницу «capabilities» (URL 404).
Безопасная ESC-страховка реализована скриптом `scenes/s5/casefile_resume.se.kts`
(переоткрывает последний диалог из `saveable currentDialogue`).
Чтобы повесить возобновление на клик по NPC, нужен точный синтаксис capability —
уточнить у автора мода и дописать сюда.

---

## 4. `saveable` между отдельными `start-script` вызовами

Состояние (`knowsEmir`, `courtGood`, `diaryCount`, `currentDialogue`) объявлено как
`saveable` и предполагается глобальным между запусками разных `.se.kts` через
`/hollowengine start-script`. Это не проверено на живом сервере — если состояние
не переживает границу скрипта, `casefile_resume` не найдёт последний диалог.
Проверить при первом прогоне.

## Чек-лист перед релизом контента
- [ ] У каждой quest-задачи есть `id`, `title`, `description`.
- [ ] У квеста указаны `prerequisites` и `rewards`.
- [ ] У диалоговых `_meta`/`entry` заполнены все строковые поля (нет null).
- [ ] Все `start-script`/импорты резолвятся в существующие файлы.
- [ ] Все `completeTask` ссылаются на существующие задачи квеста.
- [ ] Все `next` в диалогах резолвятся в файлы узлов той же папки.
